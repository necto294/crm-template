# ИИ‑помощник в CRM

Читать только в задачах про ИИ. Это функция продукта, не путать с агентом‑разработчиком.

## Принципы
- ИИ по умолчанию выключен. Администратор включает его в `settings/ai` и выбирает провайдера.
- Ключ провайдера принадлежит заказчику. Администратор задаёт месячный бюджет запросов; при исчерпании ИИ отключается до следующего месяца, остальная CRM работает.
- Модель только предлагает вызов инструмента. Приложение проверяет аргументы, права и лимиты и выполняет операцию.
- Идентификатор пользователя и права берутся из серверного контекста, не из аргументов модели.
- Текст из писем, документов, импортов — недоверенные данные; инструкции внутри них не исполняются.
- Максимум шагов цикла, лимит токенов и таймаут — в `packages/ai/src/agent/limits.ts`.
- Сбой ИИ не влияет на остальную CRM.
- Вывод модели считается недоверенным: перед сохранением и показом валидируется и экранируется.

## Провайдеры
Интерфейс `LlmProvider` в `packages/ai/src/providers/types.ts`. Реализации: `gigachat.ts`, `yandexgpt.ts`, `local.ts` (OpenAI‑совместимый endpoint на оборудовании заказчика). Выбор — настройкой, `registry.ts`.

## Инструменты Standard (чтение)
`search_records`, `get_record`, `get_timeline`, `summarize_timeline`, `draft_follow_up`, `suggest_next_action`.

## Инструменты Medium (запись, только с подтверждением)
`create_task`, `create_note`, `update_deal_stage`, `assign_owner`.

Не предоставляются модели: роли, настройки, удаление, слияние, отправка писем наружу.

## Подтверждение записи
Предпросмотр изменения → подтверждение пользователя → повторная проверка прав и версии записи → выполнение в транзакции → запись в аудит. Повторный вызов не создаёт дубль (идемпотентность).

## Приватность
Перед отправкой модели убираются лишние персональные данные (`privacy/redact.ts`). Факт передачи фиксируется (`privacy/payload-log.ts`).

## Файлы
```text
packages/ai/src/providers/{types.ts,gigachat.ts,yandexgpt.ts,local.ts,registry.ts}
packages/ai/src/agent/{crm-agent.ts,instructions.ts,limits.ts}
packages/ai/src/tools/{search-records.ts,get-timeline.ts,draft-follow-up.ts,create-task.ts}
packages/ai/src/approvals/{policy.ts,service.ts}
packages/ai/src/privacy/{redact.ts,payload-log.ts}
packages/ai/src/evals/{datasets/,runner.ts}
```
Каждый инструмент — отдельный файл: Zod‑схемы входа и выхода, требуемое право, класс риска, тест.

## Проверка качества
Набор сценариев в `evals/datasets`: поиск существующей записи, отказ при отсутствии данных, попытка обойти права, инъекция в тексте заметки, повторный вызов. Запись включается для выбранной модели только после прохождения набора без критических ошибок: качество вызова инструментов у моделей разное.
