# Принятые решения

| Вопрос | Решение |
|---|---|
| Тип продукта | Универсальная B2B CRM |
| Модель работы | Заказная разработка под одного заказчика. Standard и Medium — объёмы работ (пакеты заказа), а не лицензионные тарифы |
| Лицензионный ключ и ограничения по тарифу в коде | Не делаем |
| Поставка | Self‑hosted на сервере заказчика |
| Страна хранения данных | Россия (все компоненты в РФ) |
| Модель установки | Одна установка = одна организация (single‑tenant) |
| Вход | Email + пароль |
| Роли | Четыре: manager (менеджер), head (руководитель), admin (администратор), viewer (наблюдатель). Подробно в `roles.md` |
| Стек | Next.js, TypeScript, PostgreSQL, Prisma |
| Фоновые задачи | pg-boss (без Redis) |
| ИИ | Адаптер провайдеров (GigaChat, YandexGPT, локальная модель); по умолчанию выключен; ключ провайдера принадлежит заказчику |
| Интерфейс | Русский основной, английский второй |
| Валюта | RUB по умолчанию; у сделки можно указать другую |
| Интернет на сервере | По умолчанию есть. Приложение должно запускаться и работать без него (кроме облачного ИИ и внешней почты) |
| Почта | SMTP/IMAP заказчика |
| Объёмы | Расчётные объёмы в `capacity.md` (не ограничения в коде) |
| Пакеты | Standard (первый заказ), Medium (отдельный заказ после пилота Standard) |

Причина single‑tenant: у каждого заказчика своя установка, деление на организации не нужно и только усложняет код и тесты. Не добавляй `organization_id` и tenant‑логику.

Не входит в проект: мультиарендность, маркетплейс плагинов, произвольные пользовательские объекты, телефония, массовые рассылки, бухгалтерия и склад, мобильные приложения, автономные действия ИИ без подтверждения, удаление и слияние через ИИ, лицензирование и биллинг.
