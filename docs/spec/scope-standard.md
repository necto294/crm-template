# Standard — состав первого заказа

1. Пользователи и четыре роли (manager, head, admin, viewer; см. `roles.md`); приглашение по email; сброс пароля по email.
2. Компании: карточка, ИНН, ответственный, теги, поиск, фильтры.
3. Контакты: привязка к компаниям, телефоны +7, email.
4. Сделки: один pipeline с настраиваемыми стадиями, Kanban, сумма, валюта, вероятность, причина проигрыша.
5. Задачи и активности: заметки, звонки, встречи, задачи; общая лента в карточке.
6. Поиск по всем сущностям (PostgreSQL full‑text).
7. Импорт CSV (компании, контакты) с предпросмотром, отчётом об ошибках и обработкой дубликатов (см. 7а); экспорт CSV. Импорт выполняется в фоне.
8. Дашборд: сумма по воронке, сделки по стадиям, просроченные задачи, выиграно и проиграно за период. Менеджер видит данные по себе, руководитель и администратор — по команде.
9. Отчёт «Продажи по менеджерам» (см. 9а).
10. Уведомления: в приложении и по email (назначение, просрочка).
11. Журнал действий без хранения копий персональных данных.
12. Функции по 152‑ФЗ (см. `privacy-152fz.md`).
13. ИИ‑помощник, если включён: поиск, резюме ленты, черновик письма, подсказка следующего шага. Только чтение и текст, без записи. Видит только то, что разрешено правами пользователя.
14. Установка Docker Compose, резервное копирование, обновление одной командой.

## 7а. Дубликаты при импорте и ручное слияние

Поиск дубликатов при импорте:
- Компании сравниваются по нормализованному ИНН (только цифры), при отсутствии ИНН — по нормализованному названию (регистр, кавычки, форма собственности «ООО/АО/ИП» отбрасываются для сравнения).
- Контакты сравниваются по нормализованному email или нормализованному телефону (+7, только цифры).
- Предпросмотр импорта показывает для каждой строки статус: новая / совпадает с существующей записью / дубликат внутри файла.
- Для совпавших строк пользователь выбирает действие: пропустить, обновить существующую запись (только пустые поля или все поля — на выбор) или создать как новую. Действие можно задать сразу для всех строк.
- Итоговый отчёт содержит счётчики: создано, обновлено, пропущено, ошибки, и скачиваемый файл с ошибочными строками.
- Нечёткого поиска (опечатки, похожие названия) в Standard нет.

Ручное слияние двух записей (компании или контакта):
- Доступно ролям `head` и `admin`.
- Пользователь выбирает основную запись; для каждого поля, где значения различаются, выбирает, какое оставить.
- Связи (сделки, контакты, задачи, заметки, файлы, теги) переносятся на основную запись; вторая запись мягко удаляется и помечается как слитая.
- Операция выполняется в одной транзакции и пишется в аудит без значений персональных данных.
- Отмены слияния нет; перед выполнением показывается подтверждение с итогом.

## 9а. Отчёт «Продажи по менеджерам»

- Для каждого ответственного за период: число выигранных сделок, сумма выигранных, сумма открытых сделок в воронке, число проигранных, доля выигранных среди закрытых (выигранные / (выигранные + проигранные)).
- Фильтры: период, воронка, ответственный.
- Суммы показываются отдельно по каждой валюте. Автоконвертации курсов нет, суммы в разных валютах не складываются.
- Таблица и столбчатая диаграмма; экспорт в CSV.
- Доступ: `head` и `admin` видят всех; `viewer` видит всех в режиме чтения; `manager` видит только свою строку.

Критерий приёмки Standard: пользователь входит, администратор приглашает команду и назначает роли, импортируется CSV с обработкой дубликатов, ведутся компании/контакты/сделки/задачи, сделка перемещается по Kanban, виден дашборд и отчёт по менеджерам; все операции проверяют права на сервере по матрице из `roles.md`; приложение развёрнуто на сервере заказчика, бэкап и восстановление проверены.
