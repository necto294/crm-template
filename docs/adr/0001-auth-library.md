# 0001. Библиотека входа

Статус: не решено

## Контекст
Вход по email и паролю, argon2id, блокировка после неудачных попыток, сброс пароля по email, сессии с возможностью отзыва, роли из `docs/spec/roles.md`. Приложение работает на сервере заказчика, внешние сервисы запрещены.

## Варианты
- Auth.js (Credentials)
- Better Auth

## Критерии
Поддержка пароля и argon2id, сброс пароля, отзыв сессий, работа без внешних сервисов, зрелость и поддержка, простота тестирования.

## Решение
Используем Better Auth для аутентификации по email и паролю.

- Сессии хранятся в PostgreSQL через Prisma-адаптер Better Auth.
- Пароли хешируем argon2id. Better Auth по умолчанию использует scrypt, поэтому
  в настройке emailAndPassword.password задаём собственные функции hash и verify
  на @node-rs/argon2 (параметры: 64 МиБ памяти, 3 итерации, parallelism 4).
- Better Auth отвечает только за вход, сессии и сброс пароля. Роли и права
  остаются нашими: таблицы roles и role_permissions и проверка в packages/dal
  по docs/spec/roles.md. Плагины Better Auth для ролей не используем.
- Блокировку аккаунта после серии неудачных входов реализуем сами в
  packages/auth/src/lockout.ts. Встроенный rate limit Better Auth оставляем
  как дополнительную защиту.
- Версию better-auth фиксируем точной в lockfile.

## Последствия
Плюсы:
- Пароли, сессии, сброс пароля и отзыв сессий уже есть, не пишем с нуля.
- Работает без внешних сервисов: данные остаются в нашей PostgreSQL.
- Готовые интеграции с Next.js и Prisma.

Что нужно сделать дополнительно:
- Написать функции hash/verify на argon2id (спецификация security.md требует argon2id).
- Реализовать блокировку после неудачных попыток: rate limit не заменяет её.
- Реализовать правило «нельзя удалить или понизить последнего администратора»
  и защиту от входа заблокированных пользователей в packages/dal.
- Прокидывать Prisma-клиент из packages/db в packages/auth. Импортировать
  @prisma/client внутри packages/auth нельзя (правило 1 в AGENTS.md).
- Схему таблиц Better Auth генерируем его CLI, затем применяем через prisma
  migrate. Таблицы users и sessions синхронизируем с docs/spec/data-model.md.
- Настроить cookie (HttpOnly, Secure, SameSite), срок жизни сессии и CSRF.

Риски:
- Библиотека развивается быстро, API меняется между версиями: перед
  обновлением читать changelog и прогонять тесты входа.
- Если вход в Better Auth откажет, замена потребует переписать packages/auth.
  Поэтому весь код доступа к нему держим внутри packages/auth, а остальное
  приложение получает только свой интерфейс (getSession, requireUser).

Тесты (обязательно): вход без пароля, неверный пароль, блокировка после N попыток,
отзыв сессии, смена роли действует на следующем запросе.
